# پلنیکس | Planix Telegram Bot

بات تلگرامی برای برنامه‌ریزی روزانه و پیگیری تسک‌ها — نوشته‌شده با Go.

پنل وب: https://ag01.f1f.site

پلنیکس به هر کاربر کمک می‌کند کارهایش را ثبت کند، برنامه‌ی امروزش را ببیند و تسک‌ها را به دیگران واگذار کند و وضعیتشان را پیگیری کند. بات دوزبانه است (فارسی و انگلیسی) و کاربر از تنظیمات زبانش را عوض می‌کند.

## قابلیت‌ها

- دکمه‌های رنگی کیبورد و دکمه‌های شیشه‌ای (Bot API 9.4+)
- ثبت تسک جدید با گفتگو؛ موعد پیش‌فرض خودکار
- برنامه امروز با فیلتر (باز / انجام‌شده / همه) و صفحه‌بندی
- کارت تسک: تیک زدن، بازگشایی، ویرایش عنوان و توضیحات، انتخاب موعد و اولویت، حذف با تایید
- ارسال عکس به‌عنوان مدرک برای هر تسک و مشاهده‌ی دوباره‌ی آن (عکس فقط از تلگرام نمایش داده می‌شود و هیچ چیزی روی سرور ذخیره نمی‌شود)
- جستجو بین تسک‌ها
- پوشه‌بندی تسک‌ها با زیرپوشه؛ یک تسک می‌تواند در چند پوشه باشد و پوشه‌های دریافتی از واگذاری هم جدا دیده می‌شوند
- فیلترهای زمانی: امروز، فردا، هفته‌ی پیش‌رو و عقب‌افتاده
- واگذاری چند تسک به یک کاربر با یک پیام و اطلاع‌رسانی دوطرفه
- وضعیت وظایف واگذارشده به هر نفر
- یادآوری موعد تسک‌ها
- گزارش روزانه تا ۳ ساعت دلخواه در روز (قابل خاموش کردن و تنظیم ساعت)
- پروفایل آماری: تعداد تسک‌های باز، انجام‌شده، لغو‌شده و درصد پیشرفت
- ویرایش اطلاعات پروفایل: نام، نام خانوادگی و تایم‌زون
- پنل وب با ورود OTP؛ کد ورود را خود بات در تلگرام می‌فرستد و نشست ۳۰ روزه و لغزان است
- وب‌هوک تلگرام با اعتبارسنجی secret و اندپوینت سلامت سرویس

## معماری

پروژه لایه‌بندی استاندارد Go را دنبال می‌کند؛ جزئیات در [docs/ARCHITECTURE.fa.md](docs/ARCHITECTURE.fa.md).

```
cmd/planix/            نقطه‌ی ورود برنامه
internal/app/          چیدن اجزا: config، logger، db، bot، scheduler
internal/domain/       مدل‌های دیتابیس
internal/repository/   کوئری‌های دیتابیس
internal/service/      قواعد کسب‌وکار: تسک، پروفایل، احراز هویت
internal/bot/          رفتار بات: هندلرها، ماشین وضعیت، یادآوری‌ها
internal/bot/ui/       کیبوردها، متن‌های دوزبانه و قرارداد دکمه‌ها
internal/httpapi/      روتر Gin: سلامت سرویس، وب‌هوک و API پنل وب
internal/platform/     PostgreSQL و لاگر zap
docs/                  مستندات معماری
```

## اجرای محلی

۱. مخزن را کلون کنید (پیش‌نیاز: Go 1.25+ و Docker):

```
git clone https://github.com/AliGhanizade/planix-telegram-bot.git
cd planix-telegram-bot
```

۲. فایل `.env.example` را به `.env` کپی کنید و توکن بات را از BotFather جایگزین کنید.

۳. دیتابیس را بالا بیاورید و متغیرهای محیطی را لود کنید:

```
docker compose up -d postgres
export $(grep -v '^#' .env | xargs)
```

۴. اجرا:

```
go run ./cmd/planix
```

۵. سلامت سرویس: `http://localhost:8080/healthz`

## اجرا با داکر

```
cp .env.example .env   # توکن بات را جایگزین کنید
docker compose up -d --build
docker compose logs -f bot
```

سرویس `bot` بعد از آماده شدن PostgreSQL ساخته و اجرا می‌شود و تنظیمات را از `.env` می‌خواند.

## متغیرهای محیطی

| متغیر | الزامی | پیش‌فرض | توضیح |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | بله | — | توکن بات از BotFather |
| `DATABASE_URL` | بله | اتصال لوکال پستگرس | رشته‌ی اتصال PostgreSQL |
| `TELEGRAM_WEBHOOK_SECRET` | خیر | خالی | برای اعتبارسنجی وب‌هوک |
| `TELEGRAM_OWNER_USERNAME` | خیر | `AliGhanizade` | یوزرنیم پشتیبانی |
| `HTTP_ADDR` | خیر | `:8080` | آدرس HTTP سرور |
| `APP_ENV` | خیر | `development` | `production` یا `development` |
| `LOG_LEVEL` | خیر | `info` | `info` یا `debug` |
| `DAILY_REPORT_CRON` | خیر | `0 0 21 * * *` | زمان گزارش روزانه (cron با ثانیه) |
| `REMINDER_CRON` | خیر | `0 */15 * * * *` | فاصله‌ی بررسی یادآوری موعد |
| `REMINDER_LEAD_MINUTES` | خیر | `120` | چند دقیقه قبل از موعد، یادآوری بفرستد |
| `WEB_CORS_ORIGIN` | خیر | `*` | مبجأ مجاز CORS برای فرانت پنل وب |

## حالت وب‌هوک (برای سرور)

بات به‌صورت پیش‌فرض با لانگ‌پولینگ کار می‌کند. برای وب‌هوک، برنامه را روی HTTPS منتشر کنید و سپس:

```
https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://YOUR-DOMAIN/telegram/webhook&secret_token=<TELEGRAM_WEBHOOK_SECRET>
```

اگر `TELEGRAM_WEBHOOK_SECRET` تنظیم شده باشد، هر درخواستی بدون هدر مخفی درست با 401 رد می‌شود.

## پنل وب

پنل وب کامل و دوزبانه‌ی فارسی (RTL) داخل کانتینر جداگانه‌ی `web` اجرا می‌شود و روی پورت ۸۰ در دسترس است. قابلیت‌ها:

- ورود با یوزرنیم یا آیدی عددی تلگرام + کد OTP که بات می‌فرستد
- مدیریت کامل تسک‌ها: فهرست با فیلتر و صفحه‌بندی، جستجو، ثبت، ویرایش، حذف، تیک و بازگشایی
- مشاهده‌ی عکس مدرک هر تسک (استریم مستقیم از تلگرام)
- پروفایل با آمار، ویرایش اطلاعات و خاموش/روشن کردن گزارش روزانه
- شخصی‌سازی ظاهر: تم تاریک/روشن/سیستم، سه استایل (مات، شیشه‌ای، خطی)، چهار رنگ اصلی (صورتی، آبی، سبز، زرد) + رنگ دلخواه و اسلایدر گردی گوشه‌ی کارت‌ها و دکمه‌ها — همه فقط روی مرورگر خودت ذخیره می‌شود

جریان ورود:

۱. کاربر در فرم وب یوزرنیم تلگرامش را می‌دهد → `POST /api/auth/login/request`
۲. بات کد ۶ رقمی را در تلگرام برایش می‌فرستد
۳. کاربر کد را در فرم وارد می‌کند → `POST /api/auth/login/verify` → توکن نشست
۴. توکن در هدر `Authorization: Bearer <token>` استفاده می‌شود

مسیرهای اصلی: `/api/tasks` (ثبت، ویرایش، حذف، فهرست با فیلتر و جستجو)، `/api/profile`، `/api/stats`. نشست‌ها ۳۰ روز اعتبار دارند و با فعالیت کاربر تمدید می‌شوند.

## به‌روزرسانی سایت (بعد از اولین استقرار)

هر وقت کد تغییر کرد، کافی است روی سرور:

```
cd /opt/planix/repo
git pull
docker compose --profile tls up -d --build
```

بیلد جدید ساخته می‌شود و کانتینرها با کد تازه ری‌استارت می‌شوند؛ دیتابیس دست‌نخورده می‌ماند. برای دیدن لاگ‌ها: `docker compose logs -f bot`

## استقرار روی سرور

۱. روی سرور (لینوکس) داکر و Docker Compose را نصب کنید.
۲. مخزن را کلون کنید و فایل `.env` را بسازید:

```
cp .env.example .env
# TELEGRAM_BOT_TOKEN و DOMAIN را پر کنید
```

۳. همه‌چیز را بالا بیاورید:

```
docker compose up -d --build
```

سه کانتینر اجرا می‌شود: `postgres`، `bot` (بک‌اند + بات تلگرام) و `web` (پنل وب روی پورت ۸۰). بات مستقل از وب اجرا می‌شود؛ اگر وب قطع شود بات به کارش ادامه می‌دهد.

۴. یک رکورد A در DNS دامنه‌تان به IP سرور بدهید.
۵. برای HTTPS با گواهی خودکار، پروفایل `tls` را روشن کنید:

```
docker compose --profile tls up -d
```

کانتینر `caddy` روی ۸۰/۴۴۳ گوش می‌دهد، گواهی Let's Encrypt می‌گیرد و دامنه‌تان را به پنل وب وصل می‌کند. مقدار `DOMAIN` در `.env` باید با دامنه‌ی واقعی یکی باشد.
